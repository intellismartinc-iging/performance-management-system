## Summary

The change moves the right way: one entity per table, `pms` as the only schema, SQL files that own the tables, and no `secondaryDB`. It also breaks three things for anyone who already has a database or the KPI module:

1. A database built before this change cannot log in until its tables are brought to the new shape (finding A). Fixed on the local database with a local script.
2. Eight schema files still point at `pms.companies` and `pms.positions`, which `schema.sql` no longer creates (finding C). Not fixed. A fresh load fails.
3. `web` still has the sign-up and register pages for routes that now answer 404 (finding G). Not fixed.

One more issue was not in the handoff: the `BehavioralQuestion` entity still read `public` (finding I). Fixed in this session, with a test.

## What is good

- `synchronize: false` matches the rule that the SQL files own the tables. A wrong entity can no longer alter columns.
- One entity per table (`EmployeeDomain` replaces the duplicate auth `Employee`).
- `schema/users.sql` indexes both foreign keys.
- The role comes from the account, not from the employee row.
- The seeds ship bcrypt hashes only, and a test checks them.
- The break is written in the commit message and in the handoff, and the handoff marks what it did not run.
- The `secondaryDB` removal also removes the `mssql` dependency and the `DB_*` checks: less surface.
